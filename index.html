WHAT IS NeuroGraph (ANGP)?

NeuroGraph (ANGP — Adaptive Neural Gossip Protocol) is a new-generation decentralized Layer 1 network for DeFi and Web3 infrastructure — inspired by biological intelligence and designed to communicate, adapt, learn, and defend itself.

At its core, ANGP introduces a novel DUAL-DAG architecture that separates network intelligence from transaction execution. A Hebbian-inspired Prediction DAG continuously coordinates network behavior, while a Three-Lane deterministic DAG processes transactions at high speed.

There is no traditional consensus. No global voting round, no leader-driven coordination. Instead, consensus emerges from the collective intelligence of the network — continuously shaped by prediction, reputation, trust, and network behavior

This architectural approach enables ANGP to pursue EXTREME scalability, security, and decentralization — challenging the fundamental limitations of static blockchain architectures.

L1

Transaction Layer

L1 Transaction Layer is the entry point of the ANGP protocol stack. It accepts incoming transactions from wallets and network participants, validates cryptographic signatures, checks for double-spend conflicts against the local ledger state, and inserts valid transactions into the mempool for processing.

This layer manages the complete transaction lifecycle from initial submission through DAG inclusion and finalization. Transactions are prioritized by arrival time and processed through a Three-Lane deterministic DAG — enabling parallel validation across multiple shards while maintaining strict causal ordering guarantees.
📥TX Reception: Accepts & parses incoming transactions
🔐Signature Validation: Ed25519 verification
🔄Double-Spend Check: Conflict detection
⚡Fee Calculation: 0.1% per transaction
L2

Prediction Layer

L2 Prediction Layer is embedded within each node's main loop and generates the four-dimensional prediction vector pᵢ(t) using a Hebbian learning rule. This layer operates on the node's local view of the DAG and updates its internal weights after each consensus step.

Although logically distinct from consensus, the prediction subsystem operates on fundamentally different data structures and time scales. The separation was motivated by the need to make reasoning about invariants and failure modes more tractable.
🧠Hebbian Learning: Weight updates per step
📊Prediction Vector: 4D output pᵢ(t)
🔗DAG-Based: Local view processing
⏱️Real-Time: Embedded in main loop
L3

Consensus Layer

L3 Consensus Layer aggregates prediction vectors from peer nodes using the reputation-weighted median algorithm. It performs deterministic ordering of transactions via the DAG-based total ordering algorithm and drives the shard-consensus protocol for each of the 333 shards independently.

The consensus mechanism achieves emergent agreement without leaders or rounds—nodes converge on transaction ordering through weighted median aggregation of independent predictions, providing robustness against Byzantine adversaries.
📈Aggregation: Reputation-weighted median
🔀Total Ordering: DAG-based deterministic
🎯Shard Consensus: 333 independent instances
🛡️Byzantine Resilient: Reputation-weighted median resists adversarial nodes
L4

Reputation Layer

L4 Reputation Layer maintains per-node reputation scores using a dual-EMA (Exponential Moving Average) system. It runs 13 behavioral detectors that monitor node behavior patterns—including consensus deviation, latency anomalies, proposal validity, and message propagation consistency—feeding anomaly signals into the reputation engine.

Reputation scores are the single source of truth for node influence in the network—higher reputation means greater weight in consensus aggregation and proposal selection.
📊Dual-EMA System: Long + short term tracking
📉Certificate Decay: Time-based score reduction
⚖️Influence Weight: Prediction aggregation factor
🔍Query API: For VRF & Consensus layers
L5

Security Layer

L5 Security Layer operates 2 adaptive detectors (Coordination Attack & Adaptive Threat) that receive aggregated anomaly signals from L4's 13 behavioral detectors—the complete stack forms a 15-detector defense system. It detects sophisticated attack patterns including double-spends, theft attempts, rate violations, and clock skew anomalies across the network.

This layer can directly slash reputation scores for detected attacks, providing real-time defense against malicious actors while maintaining false-positive rates below 0.00% in testing.
🔬15 Detectors: Attack pattern recognition
⚠️Anomaly Signals: Feed to reputation engine
🚫Auto-Slash: Direct reputation penalty
🎯0% False Positive: Tested accuracy
L6

Network Layer

L6 Network Layer manages peer-to-peer communication, message routing, and network topology maintenance. It handles gossip propagation of transactions, predictions, and consensus messages throughout the network.

This layer implements the async-network abstraction that decouples protocol logic from the transport layer, enabling seamless operation over TCP, QUIC, or future transport protocols with minimal changes to upper layers.
🌐P2P Network: Peer discovery & management
📢Gossip Protocol: Message propagation
🔀Message Routing: Efficient delivery
🔌Transport Abstract: TCP/QUIC agnostic
L7

Sharding Layer

L7 Sharding Layer manages the 333-shard topology, handles cross-shard transaction routing, and maintains shard membership.

It implements an account-based sharding scheme where each account is deterministically assigned to a specific shard using consistent hashing. This enables horizontal scalability — each shard processes transactions independently while maintaining consistency through cross-shard coordination.

🔢 333 Shards: Parallel processing
👤 Account-Based: Deterministic assignment
↔️ Cross-Shard Routing: Atomic transfers
📈 Horizontal Scale: Linear throughput
L8

Slot Layer

L8 Slot Layer manages First-Come-First-Served (FCFS) slot allocation for new node admission to the network. It tracks available slots, processes join requests, and enforces a proof-of-work anti-spam gate to prevent Sybil attacks.

This layer controls the maximum network size (target: 2,664 nodes) and coordinates the entire onboarding process, ensuring new nodes integrate smoothly without disrupting ongoing consensus operations.
🎫FCFS Allocation: Fair admission order
⛏️PoW Gate: Sybil attack prevention
📊Slot Tracking: Capacity management
🚪Onboarding: Smooth integration
L9

Finality Layer

L9 Finality Layer manages batch finalization, state snapshots, and persistence. It implements the finality store that records which transaction batches have been finalized, the snapshot mechanism for state checkpoints, and the persistence backend for crash recovery.

This layer ensures 100.05% finality rate* by maintaining immutable records of confirmed transaction batches and enabling fast state reconstruction after any node restart or network partition.

* The 0.05% above 100% represents transaction fees collected by proposing nodes.

✅Batch Finalization: Immutable confirmation
📸State Snapshots: Checkpoint mechanism
💾Persistence: Crash recovery backend
🎯100.05% Rate: Finality + proposer fees

ANGP Architecture — Inter-Layer Data Flow

Data Flow

  • L1: Wallet [Ed25519] signs transactions and submits them into the Three-Lane DAG for deterministic ordering.
  • L2-L3: Hebbian 4D predictions feed weighted-median neural consensus; consensus median and prediction errors flow to L4/L5.
  • L4-L5: Dual-EMA reputation weights influence consensus; Security detects anomalies (Coordination + Adaptive) and sends penalties to L4.
  • L6-L8: Network transports all messages via P2P gossip; shards assign nodes by address hash; VRF selects proposers per slot.
  • L9: Batch finalization commits approved transactions every 5 steps at 70% threshold; receipts flow back through network layer.
